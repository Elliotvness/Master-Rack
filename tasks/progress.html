Four lenses on what remains

CI/CD · doubt-driven · frontend · git workflow

Lens 01

CI/CD and automation

What exists is above ordinary practice in one specific way worth protecting: every checker has a self-test, and the self-test runs first. A checker that silently stopped working would otherwise report a clean pass forever — the exact failure mode behind F-06 and F-08.

  • The tip is unverified. One unpushed commit means the pipeline's guarantee does not cover the code that exists.
  • No secret scanning (T-11), no dependency audit. One CI step each.
  • No bundle ceiling (P-05). Agree it before the first screen; a ceiling set after the bundle exists is one nobody meets.
  • One serial job, suite runs twice — pnpm test then pnpm coverage. Split lint / typecheck / test into parallel jobs while the pipeline is still short enough that nobody is tempted to skip it.
  • No rollback path, no release mechanics (T-26).
Lens 02

Doubt-driven development

Already the project's strongest habit, and the reason today's numbers hold up. Five defects landed in one day and four were found by building the control that was supposed to already exist, not by reading code.

The pattern has a name worth keeping in front of the next three tasks: a control that states its own method and has no mechanism behind it.

  • T-13b, the outbound validator — a validator never fed a forbidden field passes forever. Plant one, watch it go red.
  • T-13d, idempotency — a uniqueness constraint nothing races is untested. The concurrency test is the control; the constraint alone is not.
  • T-14, deny-by-default — a route-coverage assertion run against a fixture instead of the real router is F-02 again, one layer up.
  • AC-06 is still enforced against a model. The route table is asserted against no router because none exists. T-15 is what converts it.
Lens 03

Frontend UI engineering

Zero .tsx files, so every decision here is still free — and the cheapest it will ever be.

  • P-05 first. LCP ≤ 2.5 s, CLS ≤ 0.1, initial JS ≤ 200 KB gzipped — and INP ≤ 200 ms is the one that matters: a rack configurator is an interaction loop, not a page view. The 120 ms preview budget covers the computation; nothing covers the paint.
  • T-17 carries the architecture. The renderer consumes the display list and never recomputes. Screen and output diverging as separate code paths is what fragmented all four prior projects.
  • T-16 tokens before components. This product exists to protect a commercial position; a templated look undercuts that. Spacing scale, type hierarchy, semantic colour tokens, never colour alone for state.
  • WCAG 2.1 AA is a Checkpoint C gate, not a polish pass. Keyboard traversal and focus management belong in T-16, and every screen gets its empty, loading and error states from the start.
  • T-21 audits the auditor — self-tested against known contrast ratios before it is trusted to report.
Lens 04

Git workflow and versioning

  • Merge the branch. 27 commits, well past short-lived, and the name no longer describes the contents.
  • Push the tip. One commit is standing outside every guarantee the project has.
  • One short-lived branch per task from Phase 2 on, merged within a day or two. The tasks are already sized for it.
  • No tags, no changelog, version 0.0.0. Fine today — nothing consumes this yet. The moment the pilot organisation touches a deployed build, that stops being true, and a changelog reconstructed later is one with half its entries missing. T-26 lands with the first deploy, not after it.
  • Write the changelog entry in the commit that makes the change.

Update cadence

Standing rule — a scoreboard refreshed only on request becomes another stale document

This page and tasks/progress.md are updated whenever a long task completes, or a batch of several tasks completes — unprompted, before the session ends.

  1. Re-measure, don't re-read. Run the commands again against the working tree. Figures copied from the previous scoreboard are claims, not measurements.
  2. Recompute done-points over the 143-point denominator using the plan's own sizes. Completion stays binary.
  3. Re-check §15.2. It is the headline, and it does not move until HTTP and a screen exist.
  4. Label every figure verified-today or repository-claim. Anything that could not be re-run goes in the claims list, with the reason.
  5. Record new drift found while measuring, with its owning task.
  6. Update all four copies. tasks/progress.md and tasks/progress.html in the repo, this published page, and the Claude Project doc. Republish to the same URL, never a new one.
  7. Know what the gate covers. pnpm check:scoreboard compares the two repo files and nothing else — two of the four copies. A green build says nothing about this page or the project doc; CI cannot reach either. Re-read and compare both by hand.
  8. Re-date, and say if the denominator moved. A percentage that changed because the denominator changed is not progress.
