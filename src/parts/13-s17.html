17Reference-project inventory, reuse matrix and migration

Change-control rule — absolute

The four projects under C:\Rack Master\Resourse (do not delete or overwrite files)\ are read-only research sources. Nothing in them is edited, deleted, moved, renamed or written to, ever. Nothing found in them is assumed correct or final. This blueprint is the governing direction; where it contradicts a prior decision, the contradiction is recorded explicitly (§17.5) rather than routed around.

ConflictResolution for Rack Master Studio
Two live, incompatible domain models: rack-app (frozen dataclasses, hand-audited units, geometry-first, Python 3.11) vs rack-engine (pydantic, pint, type-first, Python 3.13).Neither. A new TypeScript model that takes rack-app's revision and edit machinery and rack-engine's BayType grouping, connector_series, picking-level distinction and pallet tabulation.
Prototype vs packages in rack-studio: a complete second implementation in untyped JS. The prototype is ahead on rules (15 vs 0) and checks (11 vs ~5); the packages are ahead on types, lifecycle, BOM and persistence. Neither is a superset. 17.4 Migration approach

  1. Copy, never move. The four trees stay exactly as they are. Ported code is copied into the new repository and re-tested there under the new boundary rules.
  2. Port the data first. The verified catalog is the most expensive asset and everything else depends on it. It arrives as declarative files with every provenance field intact, and it re-enters DRAFT status until a named second person approves it in the new system — machine reconciliation is evidence, not a signature.
  3. Port assertions before implementations. Write the test first, from the reference project's assertion, then port the code until it passes. An assertion that is not carried over is a claim that quietly stops being checked.
  4. Port the doctrine before either. The twelve rules, the status vocabulary and the source hierarchy are policy documents, and they cost nothing to adopt on day one.
  5. Track every drop. Anything rejected for lack of a source becomes a tracked open item with a named owner, not a silent omission. That register — wire decks, row spacers, footplates, rates — is the roadmap for BOM completeness.
  6. Keep the Carson acceptance case. 916 bays, 6,980 gross, 156 lost, 6,824 net, 324 picking levels, reproduced from a delivered drawing. It is the only end-to-end validation against a real job anywhere in the four projects, and it must go red if the new engine gets counts wrong.
